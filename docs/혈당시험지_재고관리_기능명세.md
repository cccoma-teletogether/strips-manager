# 혈당시험지 재고관리 기능명세

## 1. 목적

혈당시험지 재고를 시험지 종류별로 관리하고, **유효기간**과 **개봉 후 사용기간**을 함께 기준으로 삼아 먼저 만료되는 재고(통/바이알)부터 사용하도록 돕는다.

이 문서의 목표는 단순 재고 수량 관리가 아니라, **폐기 손실을 줄이고 사용 우선순위를 명확히 하는 운영 기준**을 정의하는 것이다. (CGM 재고관리 앱과 동일한 설계 원칙을 따른다.)

## 2. 범위

### 포함
- 시험지 종류 등록 및 관리 (제품명, 호환 측정기, 개봉 후 사용기간, GTIN, 모델명)
- 재고 개별 등록 (통/바이알 단위)
- 유효기간 관리
- 개봉일 관리
- 상태 계산 및 우선순위 정렬
- 만료 임박 알림 기준
- 사용 시작, 사용 종료, 폐기 처리
- 바코드/GS1 스캔으로 LOT·유효기간 자동 입력
- 개봉 이력 기반 월평균 사용량 계산 및 구매 수량 제안
- 백업 및 복원

### 제외
- 통 내 남은 매수(장) 추적 — 통 단위로만 상태를 관리한다.
- 서버 연동, 다중 사용자 권한
- 외부 병원 시스템 연동, 구매 발주 자동화

## 3. 핵심 원칙

1. 각 시험지 통(바이알/박스)은 **개별 재고 항목**으로 관리한다. 통 안의 매수는 추적하지 않는다.
2. 재고의 사용 우선순위는 **실효 종료일**이 가장 빠른 순서로 정한다.
3. 실효 종료일은 아래 두 날짜 중 더 이른 날짜를 사용한다.
   - 시험지 자체 유효기간
   - 개봉 후 사용기간 종료일
4. 사용중 통과 미개봉 통은 상태를 분리해서 보여준다.
5. 모든 경고는 오늘 날짜를 기준으로 계산한다.

## 4. 사용자 목표

- 지금 써야 할 시험지 통을 한눈에 확인한다.
- 곧 만료될 시험지를 미리 파악한다.
- 시험지 종류별 재고 분포를 확인한다.
- 개봉 후 사용기간을 넘긴 통을 놓치지 않는다.
- 오래 남은 재고보다 먼저 버려질 재고를 우선 사용한다.

## 5. 화면 구성

### 5.1 대시보드
- 현재 사용중인 시험지 통
- 오늘 만료 또는 곧 만료되는 재고 수
- 시험지 종류별 재고 수량
- 우선 사용 대상 목록
- 경고 배지

### 5.2 재고 목록
필터: 시험지 종류 / 상태(미개봉, 사용중, 곧만료, 만료, 폐기)
정렬: 실효 종료일 오름차순(기본) / 개봉일 오름차순 / 등록일 최신순
카드 표시: 시험지 종류명, LOT, 유효기간, 개봉일, 실효 종료일, 상태

### 5.3 재고 등록 / 수정
입력 필드: 시험지 종류(필수), 유효기간(필수), LOT(선택), 박스/바이알 코드(선택), 개봉일(선택), 메모(선택)
이미지(카메라/파일) 또는 GS1 원문 텍스트로 스캔 입력 가능

### 5.4 상세 모달
표시: 시험지 종류, LOT, 유효기간, 개봉일, 개봉 후 사용기간, 실효 종료일, 상태, 메모
동작: 사용 시작 / 사용 종료 / 폐기 처리 / 수정 / 삭제

### 5.5 설정
- 알림 기준일 (만료 임박 판단 일수)
- 시험지 종류 관리 (이름, 호환 측정기, 개봉 후 사용기간, 색상, GTIN, 모델명)
- 데이터 내보내기 / 불러오기 (JSON)
- 전체 초기화

## 6. 데이터 구조

```javascript
{
  stripTypes: [
    {
      id: "caresens_n",
      name: "CareSens N",
      meter: "CareSens N 측정기",
      openUseDays: 90,
      color: "#0d9488",
      gtin: "",
      model: ""
    }
  ],
  inventory: [
    {
      id: "inv_001",
      typeId: "caresens_n",
      lot: "250701C001",
      boxCode: "",
      expiry: "2026-12-31",
      openedAt: null,
      notes: "",
      archived: false,
      archivedAt: null,
      createdAt: "2026-06-08T10:00:00Z"
    }
  ],
  settings: {
    alertDays: 30,
    forecastMonths: 3
  }
}
```

## 7. 상태 정의

### 7.1 상태 목록
- `ready`: 미개봉
- `in_use`: 사용중
- `warning`: 곧만료
- `expired`: 만료
- `archived`: 폐기

### 7.2 상태 판정 규칙
1. `archived = true` 이면 `archived`
2. 실효 종료일이 오늘보다 이전이면 `expired`
3. 실효 종료일까지 `alertDays` 이하로 남으면 `warning`
4. 위에 해당하지 않고 `openedAt`가 있으면 `in_use`
5. 위에 해당하지 않으면 `ready`

## 8. 날짜 계산 규칙

### 8.1 개봉 후 사용기간 종료일
```text
openedAt + openUseDays
```

### 8.2 실효 종료일
```text
실효 종료일 = min(유효기간, 개봉 후 사용기간 종료일)
```
개봉하지 않은 재고는 실효 종료일을 유효기간으로 본다.

### 8.3 우선 사용 순서
1. 실효 종료일이 빠른 항목
2. 사용중 항목 우선
3. 개봉일이 빠른 항목
4. 등록일이 빠른 항목

## 9. 알림 규칙
기본 알림 기준은 `alertDays = 30`이다.

표시 색상: `warning` 주황 / `expired` 빨강 / `archived` 회색 / `ready` 파랑 / `in_use` 초록

## 9-1. 구매 예측

개봉 이력(`openedAt`)을 월별로 집계해 시험지 종류별 **월평균 사용량**을 계산하고, 이를 근거로 구매 수량을 제안한다.

### 계산 방식
1. 해당 종류에서 `openedAt`이 있는 재고를 모두 모은다 (사용중/폐기 모두 포함).
2. 가장 이른 개봉월부터 이번달까지의 개월 수(`monthSpan`)를 구한다.
3. `월평균 사용량 = 개봉 건수 / monthSpan`
4. `예상 소진 개월수 = 현재 미개봉 재고 수 / 월평균 사용량`
5. `구매 제안 수량 = max(0, ceil(월평균 사용량 × 목표 재고 개월수 − 현재 미개봉 재고 수))`

### 표시
- 개봉 이력이 없는 종류는 "데이터 부족"으로 표시하고 제안하지 않는다.
- 집계 기간이 2개월 미만이면 "데이터 적음(참고용)"으로 표시해 신뢰도가 낮음을 알린다.
- 목표 재고 개월수는 설정에서 조정 가능하며 기본값은 3개월이다 (`settings.forecastMonths`).

## 10. 사용 흐름

1. 입고: 시험지 종류 선택 → LOT 입력 → 유효기간 입력 → 저장
2. 사용 시작: 재고 선택 → 개봉일 입력 → 상태 `in_use`로 전환
3. 사용 종료: 재고 선택 → 소진 처리 → `archived`로 전환
4. 폐기: 재고 선택 → 폐기 처리 → `archived`로 전환, 목록에서 별도 구분

## 11. 시험지 종류 관리
항목: 이름, 호환 측정기, 개봉 후 사용기간, 색상, GTIN, 모델명
- 이름은 사용자 표시용이며 실제 판정은 `id` 기준.
- GTIN이 있으면 스캔 시 종류 자동 매칭에 활용.

## 12. 검증 규칙
- 시험지 종류, 유효기간 필수
- 유효기간은 오늘 이전만 아니면 허용
- 사용중 재고의 개봉일 변경 시 실효 종료일을 재계산

## 13. 백업 / 복원
- 백업: 현재 localStorage 데이터를 JSON으로 내보낸다 (`stripTypes`, `inventory`, `settings`, `version` 포함).
- 복원: JSON 파일을 불러와 localStorage에 반영한다.

## 14. 구현 우선순위
1. 데이터 구조 정의
2. 날짜 계산 함수 구현
3. 상태 판정 함수 구현
4. 재고 등록/수정 화면 (+ 바코드 스캔)
5. 목록 및 상세 화면
6. 대시보드 요약
7. 설정 및 백업/복원

## 15. 완료 기준
- 시험지 종류별 재고를 등록할 수 있다.
- 개봉일과 유효기간을 함께 계산할 수 있다.
- 만료 임박 순으로 재고를 보여줄 수 있다.
- 상태별 필터가 동작한다.
- 바코드/GS1 스캔으로 LOT·유효기간을 자동 입력할 수 있다.
- 백업과 복원이 된다.
