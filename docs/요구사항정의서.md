## 1. 문서 목적

이 문서는 StripsMgr의 요구사항을 기능/비기능 단위로 상세히 정의하여, 이후 기능 추가·변경·회귀 테스트의 기준(baseline)으로 삼기 위해 작성한다. [기능명세](./혈당시험지_재고관리_기능명세.md)가 핵심 운영 원칙과 데이터 구조를 요약한 문서라면, 이 문서는 실제 구현된 모든 기능을 추적 가능한 요구사항 ID(FR/NFR) 단위로 상세 기술한다.

## 2. 프로젝트 배경

- 사용자는 혈당시험지(CareSens N, 바로잰 등)를 통(바이알) 단위로 다수 보유하며, 유효기간과 개봉 후 사용기간을 모두 고려해 먼저 만료되는 것부터 사용해야 한다.
- 선행 프로젝트인 "CGM재고관리"(CGM 센서 재고관리 앱)와 동일한 설계 철학 — 실효 종료일 기반 우선순위, 상태 기반 경고, 개인용 로컬 저장 — 을 혈당시험지 도메인에 맞게 재구현한다.
- 서버/백엔드 없이 정적 파일만으로 동작하며 GitHub Pages로 호스팅한다. 모든 데이터는 사용자 브라우저의 `localStorage`에만 저장되고 외부로 전송되지 않는다.

## 3. 용어 정의

| 용어 | 정의 |
|---|---|
| 시험지 종류 (Strip Type) | 제품 단위 분류(예: 케어센스 N, 바로잰). 이름/호환 측정기/개봉 후 사용기간/색상/GTIN/모델명/포장 매수를 가진다. |
| 재고 항목 (Inventory Item) | 시험지 통(바이알/박스) 1개를 나타내는 개별 레코드. 통 내부의 낱장 매수는 추적하지 않는다. |
| 유효기간 (Expiry) | 제품 라벨에 인쇄된 사용기한. |
| 개봉일 (Opened At) | 해당 통을 처음 개봉한 날짜. |
| 개봉 후 사용기간 (Open-Use Days) | 개봉 이후 안전하게 사용할 수 있는 일수 (시험지 종류별로 설정). |
| 실효 종료일 (Effective End Date) | `min(유효기간, 개봉일 + 개봉후사용기간)`. 미개봉 재고는 유효기간과 동일. |
| 상태 (Status) | `ready`(미개봉) / `in_use`(사용중) / `warning`(곧만료) / `expired`(만료) / `archived`(폐기) 중 하나. |
| GS1 | 바코드/2D코드에 쓰이는 국제 표준 데이터 포맷(AI 01=GTIN, 10=LOT, 17=유효기간, 21=일련번호). |
| TASK-NNN | `changelog.md`에 기록되는 개별 작업 단위 식별자. |

## 4. 이해관계자 및 사용자

- **1차 사용자**: 혈당시험지를 구매·보관·사용하는 개인(및 보호자). 다중 사용자/권한 분리는 요구되지 않는다.
- **운영자 겸 개발자**: 동일 인물이 기능 요청과 코드 변경을 겸함. 별도 QA/운영 조직 없음.

## 5. 범위

### 5.1 포함 (In Scope)
- 시험지 종류 등록/수정/삭제 관리
- 재고(통) 등록/수정/삭제, 사용 시작/사용 종료/폐기 처리
- 유효기간·개봉일 기반 상태 자동 판정 및 우선순위 정렬
- 대시보드 요약(통계, 현재 사용중, 우선 사용 대상, 종류별 현황, 구매 예측)
- GS1 바코드 실시간 카메라 스캔 및 이미지 업로드 스캔, GS1 원문 수동 입력
- 작업기록(changelog) 탭
- JSON 백업/복원, 전체 초기화
- 만료 임박 브라우저 알림(Notification API)
- PWA(매니페스트 + 서비스워커) 및 오프라인 자산 캐시
- GitHub Pages 정적 호스팅, `index.html` → `strips-manager.html` 리다이렉트

### 5.2 제외 (Out of Scope)
- 통 내부 낱장 매수(잔여 매수) 추적
- 서버/백엔드, 사용자 계정, 로그인, 다중기기 동기화
- 다중 사용자 권한 분리
- 외부 병원/약국 시스템 연동
- 구매 발주 자동화(실제 주문 실행) — 구매 "제안"까지만 제공
- 결제, 전자상거래 기능

## 6. 기능 요구사항 (Functional Requirements)

### 6.1 시험지 종류 관리

| ID | 요구사항 |
|---|---|
| FR-001 | 시스템은 시험지 종류를 이름(필수), 호환 측정기(선택), 개봉 후 사용기간(필수, 일 단위, 1 이상), 색상(선택, 기본값 `#0d9488`), GTIN(선택), 모델명(선택), 포장 매수(선택)로 등록할 수 있어야 한다. |
| FR-002 | 시스템은 최초 실행 시 실사용 제품 2종(케어센스 N: GTIN `08809126640358`, 바로잰: GTIN `08809126641195`, 각 개봉후사용기간 90일·50매입)을 기본 시험지 종류로 제공해야 한다. |
| FR-003 | 시스템은 기존 시험지 종류를 수정할 수 있어야 하며, 식별은 내부 `id`로 하고 이름 변경은 과거 재고 데이터에 영향을 주지 않아야 한다. |
| FR-004 | 시스템은 해당 종류를 참조하는 재고 항목이 하나라도 있으면 그 시험지 종류의 삭제를 거부하고 사용자에게 알려야 한다. |
| FR-005 | 재고 등록 폼, 필터, 스캔 자동 매칭용 종류 선택 목록은 시험지 종류가 추가/삭제될 때마다 동기화되어야 하며, 기존 선택값은 가능하면 유지되어야 한다. |

### 6.2 재고(통) 관리

| ID | 요구사항 |
|---|---|
| FR-010 | 시스템은 재고 항목을 시험지 종류(필수), 유효기간(필수), LOT(선택), 박스/바이알 코드(선택), 개봉일(선택), 메모(선택)로 등록할 수 있어야 한다. |
| FR-011 | 시스템은 등록된 재고 항목을 수정할 수 있어야 하며, 수정 시 실효 종료일·상태가 즉시 재계산되어야 한다. |
| FR-012 | 시스템은 재고 상세 화면에서 "사용 시작" 동작을 제공해야 하며, 실행 시 개봉일을 오늘 날짜로 설정해야 한다. |
| FR-013 | 시스템은 재고 상세 화면에서 "사용 종료" 동작을 제공해야 하며, 실행 시 `archived=true`, `archivedAt=오늘`로 설정해야 한다. |
| FR-014 | 시스템은 재고 상세 화면에서 "폐기" 동작을 제공해야 하며, 효과는 FR-013과 동일하되 사용자에게 다른 안내 문구(폐기 처리됨)를 보여줘야 한다. |
| FR-015 | 시스템은 재고 항목 삭제 전 확인 대화상자를 띄워야 하며, 삭제는 되돌릴 수 없음을 안내해야 한다. |
| FR-016 | 시스템은 동일 시험지 종류 내에서 (일련번호 또는 LOT+유효기간)이 일치하는 기존 재고가 있으면 저장 전 중복 가능성을 경고하고 계속 여부를 사용자에게 확인해야 한다(구현 시 보류/보강 가능한 선택 요구사항). |

### 6.3 상태 판정 및 정렬 로직

| ID | 요구사항 |
|---|---|
| FR-020 | 시스템은 재고 항목마다 개봉 후 사용기간 종료일을 `개봉일 + 개봉후사용기간`으로 계산해야 한다 (미개봉 시 계산하지 않음). |
| FR-021 | 시스템은 실효 종료일을 `min(유효기간, 개봉후사용기간 종료일)`로 계산해야 한다. 미개봉 재고의 실효 종료일은 유효기간과 같다. |
| FR-022 | 시스템은 다음 우선순위로 상태를 판정해야 한다: ① `archived=true`이면 `archived` ② 실효 종료일이 오늘보다 이전이면 `expired` ③ 실효 종료일까지 설정된 "알림 기준일" 이하로 남았으면 `warning` ④ 개봉일이 있으면 `in_use` ⑤ 그 외 `ready`. |
| FR-023 | 시스템은 재고 목록을 다음 세 가지 기준으로 정렬할 수 있어야 한다: 실효 종료일 오름차순(기본), 개봉일 오름차순, 등록일 최신순. |
| FR-024 | "실효 종료일 오름차순" 정렬의 동점 처리 순서는 다음과 같아야 한다: ① 실효 종료일 ② 사용중 여부(사용중 우선) ③ 개봉일 ④ 등록일. |
| FR-025 | 시스템은 재고 목록을 시험지 종류 및 상태(`ready`/`in_use`/`warning`/`expired`/`archived`)로 필터링할 수 있어야 한다. |

### 6.4 대시보드

| ID | 요구사항 |
|---|---|
| FR-030 | 대시보드는 폐기를 제외한 전체 재고 수, 미개봉 수, 사용중 수, 곧만료/만료 수를 카드 형태로 요약해야 한다. |
| FR-031 | 대시보드는 개봉일이 있고 폐기되지 않은 모든 재고를 실효 종료일 오름차순으로 모아 "현재 사용중인 시험지" 패널에 표시해야 하며, 해당 재고가 없으면 패널을 숨겨야 한다. (CGM재고관리의 "현재 사용중 센서" 카드에 대응. 동시에 여러 종류 개봉을 허용한다는 점이 CGM과 다름.) |
| FR-032 | 대시보드는 "알림 기준일" 이내에 실효 종료일이 도래하는 폐기되지 않은 재고를 실효 종료일 오름차순 상위 8건까지 "우선 사용 대상"으로 표시해야 한다. |
| FR-033 | 사용자는 "시험지 종류 현황" 목록의 항목을 클릭해 "우선 사용 대상"을 해당 종류로 필터링/해제할 수 있어야 한다. |
| FR-034 | 대시보드는 시험지 종류별 보유 수량, 곧만료 수, 사용중 수를 요약해야 한다. |
| FR-035 | 대시보드는 "구매 예측" 패널을 표시해야 한다 (§6.6 참조). |

### 6.5 재고 목록

| ID | 요구사항 |
|---|---|
| FR-040 | 재고 목록 화면 상단에도 FR-031과 동일한 "현재 사용중인 시험지" 패널을 표시해야 한다. |
| FR-041 | 재고 목록의 각 카드는 시험지 종류, LOT, 유효기간, 실효 종료일, 상태, (개봉된 경우) 개봉일~종료 예정일을 표시해야 한다. |
| FR-042 | 각 카드는 "상세"와 "수정" 동작 버튼을 제공해야 한다. |
| FR-043 | 유효기간은 화면 폭(모바일 640px 이하 포함)에 관계없이 카드 내에서 항상 보여야 한다. |

### 6.6 구매 예측

| ID | 요구사항 |
|---|---|
| FR-050 | 시스템은 시험지 종류별로, 개봉일이 기록된 모든 재고(사용중/폐기 불문)를 월별로 집계해 "월평균 사용량(개/월)"을 계산해야 한다. 계산식: `개봉 건수 ÷ (최초 개봉월부터 이번달까지의 개월 수)`. |
| FR-051 | 개봉 이력이 전혀 없는 시험지 종류는 "데이터 부족"으로 표시하고 구매 수량을 제안하지 않아야 한다. |
| FR-052 | 집계 기간이 2개월 미만이면 수치는 표시하되 "데이터 적음(참고용)" 표시로 신뢰도를 낮게 안내해야 한다. |
| FR-053 | 시스템은 `예상 소진 개월수 = 미개봉 재고 수 ÷ 월평균 사용량`을 계산해 표시해야 한다. |
| FR-054 | 시스템은 `구매 제안 수량 = max(0, ceil(월평균 사용량 × 목표 재고 개월수 − 미개봉 재고 수))`를 계산해 표시해야 한다. |
| FR-055 | "목표 재고 개월수"는 설정 화면에서 1 이상의 정수로 사용자가 조정할 수 있어야 하며 기본값은 3이어야 한다. |

### 6.7 GS1 바코드 스캔

| ID | 요구사항 |
|---|---|
| FR-060 | 시스템은 `getUserMedia`로 후면 카메라를 직접 열어 실시간 영상 프레임에서 바코드를 자동 인식해야 한다 (파일 입력의 `capture` 속성에 의존하지 않는다 — 기기별로 갤러리가 열리는 문제가 있었음, TASK-007 참조). |
| FR-061 | 실시간 스캔은 약 0.7초 간격으로 프레임을 캡처해 디코딩을 시도해야 하며, 인식에 성공하면 자동으로 카메라를 종료해야 한다. 사용자는 "카메라 중지" 버튼으로 언제든 수동 종료할 수 있어야 한다. |
| FR-062 | 카메라를 열 수 없는 경우(권한 거부, 기기 미지원 등) 시스템은 구체적인 오류 메시지와 함께 "이미지 불러오기" 대안을 안내해야 한다. |
| FR-063 | 시스템은 이미지 파일을 업로드해 바코드를 인식하는 대체 경로를 제공해야 한다. |
| FR-064 | 바코드 디코딩은 `zxing-wasm`(1순위)과 `@zxing/library`(JS, 보조)를 함께 사용해야 하며, 1순위 실패 시 크롭·명암 보정 등 보정 시도를 거쳐야 한다. |
| FR-065 | 시스템은 GS1 원문 텍스트(예: `(01)08809126640358(17)270710(10)AD6112201` 또는 구분자 없는 압축 형식)를 직접 입력해 해석하는 수동 입력 경로를 제공해야 한다. |
| FR-066 | GS1 파싱 결과에서 AI 01(GTIN)이 등록된 시험지 종류와 일치하면 해당 종류를 자동 선택해야 한다. AI 17(유효기간, YYMMDD)과 10(LOT)은 각각 유효기간/LOT 입력란에 자동 반영해야 하며, AI 21(일련번호)은 박스/바이알 코드란에 반영해야 한다. |

### 6.8 작업기록(changelog)

## 8. 데이터 요구사항

### 8.1 데이터 모델

```javascript
state = {
  stripTypes: [
    {
      id: string,            // 내부 식별자, 예: "caresens_n"
      name: string,          // 표시용 이름
      meter: string,         // 호환 측정기 (선택)
      openUseDays: number,   // 개봉 후 사용기간(일), 1 이상
      color: string,         // HEX 색상
      gtin: string,          // GS1 GTIN (선택, 스캔 자동매칭에 사용)
      model: string,         // 모델명 (선택)
      packCount: number|null // 포장 매수 (선택, 정보 표시용)
    }
  ],
  inventory: [
    {
      id: string,
      typeId: string,        // stripTypes[].id 참조
      lot: string,
      boxCode: string,       // 박스/바이알 고유 코드 (선택)
      expiry: string,        // ISO 날짜 (YYYY-MM-DD), 필수
      openedAt: string,      // ISO 날짜 또는 빈 문자열
      notes: string,
      archived: boolean,
      archivedAt: string,    // ISO 날짜 또는 빈 문자열 (사용종료/폐기 시점)
      createdAt: string      // ISO 8601 타임스탬프
    }
  ],
  settings: {
    alertDays: number,       // 기본 30
    notifyEnabled: boolean,  // 기본 false
    forecastMonths: number   // 기본 3
  }
}
```

### 8.2 상태 전이

```
ready --[사용 시작]--> in_use --[사용 종료]--> archived
ready --[폐기]--> archived
in_use --[폐기]--> archived
(ready|in_use) --[실효 종료일 임박]--> warning (자동, 되돌아갈 수도 있음)
(ready|in_use|warning) --[실효 종료일 경과]--> expired (자동)
```
`archived`만 사용자 동작으로 도달하며, `warning`/`expired`/`ready`/`in_use`는 날짜 계산에 따라 매 렌더링마다 자동 재평가된다(영구 저장되는 상태 필드가 아님).

### 8.3 저장 키

| 키 | 용도 |
|---|---|
| `strips_v1` | 메인 상태(`stripTypes`/`inventory`/`settings`) |
| `strips_notified` | 당일 중복 알림 발송 방지 기록 |

## 11. 제약사항 및 가정

- 통 내 낱장 매수는 추적하지 않는다는 전제(사용자 확정 요구사항)이므로, "구매 예측"은 통(바이알) 개수 기준으로만 계산한다.
- 기기 간 데이터 동기화가 없으므로, 여러 기기에서 사용할 경우 사용자가 JSON 백업/복원으로 수동 동기화해야 한다.
- 비공개(Private) GitHub 저장소로 전환해도 GitHub Pages 사이트 자체는 URL을 아는 사람에게 공개된다(Enterprise Cloud 제외) — 현재 저장소는 공개로 운영한다.
- 카메라 스캔 성공률은 디바이스 카메라 성능·조명·라벨 상태에 좌우되며, 실패 시 GS1 원문 수동 입력이 항상 가능해야 한다(필수 폴백).
